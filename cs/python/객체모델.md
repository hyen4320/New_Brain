## 결론
Python 변수는 값을 담는 상자가 아니라 **객체에 붙은 이름표**입니다. `=`는 이름표를 붙이고, `+=`는 "객체 고치기(가능하면) → 이름표 다시 붙이기" 두 단계입니다.

## 핵심 정의
- **바인딩**: `a = x`는 객체를 복사하지 않고, 같은 객체에 이름 `a`를 하나 더 붙인다. 같은 객체인지는 `id()`/`is`로 확인한다.
- **인자 전달**: 호출하면 함수의 매개변수 이름이 바깥과 **같은 객체**에 붙는다. Java의 참조 전달과 같은 감각이다.
- **`a += b`** ≈ `a = a.__iadd__(b)`. `__iadd__`가 없으면 `a = a.__add__(b)`를 쓴다.
  - 가변 객체(list): `__iadd__`가 제자리에서 고치고 자기 자신을 반환 → 같은 객체
  - 불변 객체(str, int, tuple): `__add__`가 새 객체를 반환 → 이름표만 옮겨짐
- **`b = b + [99]`**: `__add__`가 새 리스트를 만들고 이름표 `b`를 그쪽으로 옮긴다. 원래 객체는 그대로다.

## 직관 — 왜 이런가
- 함수 안에서 매개변수에 **대입**하면 지역 이름표만 옮겨지므로 바깥에 영향이 없다. **객체를 고치면** 같은 객체를 보는 바깥 이름에도 보인다.
- Java로 옮기면: `a.addAll(...)`는 바깥에 보이고, `b = new ArrayList<>(b)`는 안 보인다.

## 반례 / 깨지는 조건
- `t = ([1, 2],); t[0] += [3]` → ① 리스트 `__iadd__` 성공 → ② 튜플 칸 대입 실패. **에러가 났는데 값은 바뀌어 있다.** "에러면 아무것도 안 바뀐다"는 믿음의 반례.

## 트레이드오프 · 쓰지 말아야 할 때
- 함수가 인자로 받은 리스트에 `+=`를 쓰면 호출한 쪽 데이터가 바뀐다. 의도한 게 아니면 `x = x + [...]`를 쓰거나 복사본을 만든다.
