# 3. 장기 (약 3년 ≈ 900시간)

**지향점:** 모든 분야에서 "직접 만들고, 왜 그렇게 되는지 도출하고, 깨지는 조건(반례)을 보일 수 있는" 제너럴리스트를 목표로 합니다.

**Java 배치 근거**

- **H2 후반에 시작하는 이유:** Python으로 자료구조를 직접 구현해 둔 뒤라, Java 컬렉션·제네릭·equals/hashCode를 "내가 만든 것과 무엇이 다른가"로 비교할 수 있습니다.
- **Java 언어를 1과 2로 나눈 이유:** 동시성·JMM·GC는 스레드와 메모리 같은 OS 개념이 선행입니다. 그래서 Java 2는 시스템 기초 뒤에 둡니다.
- **Java 2를 백엔드 직전에 두는 이유:** Spring의 스레드 모델, 커넥션 풀, 트랜잭션 경계를 이해하려면 Java 동시성이 선행입니다.
- **디자인 패턴의 위치:** 처음에는 Java 직후에 두었는데 백엔드 단계로 옮겼습니다. Java 언어 트랙에 시간을 주는 대신, 패턴은 실제 코드(자기 백엔드)에 적용하고 트레이드오프를 기록하는 방식으로 진행합니다.

## 3-3. 의존 관계 (장기)

```
[수학 상시 트랙: 메인과 병렬, 매주 일요일]
이산수학 ──→ 선형대수 ──→ 미적분 ──→ 확률·통계 ──→ 최적화 ──→ AI
  │  └(정수론)──────────────────────────────→ 보안(암호 원리)
  ▼
[메인 트랙: 순차, 한 번에 하나]
Python 실행모델 → DS&A 1 → 알고리즘 2 → Java 언어 1 → 시스템 기초 → Java 언어 2 → 백엔드(+패턴·TDD) → 프론트엔드 → 보안 집중 → AI → 캡스톤
                   │                      ▲                  │            ▲              │             │
                   └─(자료구조 구현 비교)──┘                  └─(스레드·메모리)┘              └─ 보안 체크 내장(병렬) ─┘
```

- **순차:** 메인 트랙은 위 순서대로 하나씩 진행합니다. Java 언어 트랙도 메인 트랙 자리를 쓰므로 다른 메인 분야와 동시에 진행하지 않습니다.
- **병렬:** 수학 트랙은 항상 병렬입니다(Java 트랙 동안에는 선형대수). 보안은 백엔드·프론트 단계마다 "보안 통과 기준 1개"로 병렬로 들어가고, 이후 집중 분기에서 순차로 다룹니다.
- **프론트가 백엔드 뒤인 이유:** 자기 API에 연결해야 CORS·인증·세션 같은 경계 문제를 실제로 겪을 수 있기 때문입니다.
- **AI가 맨 뒤인 이유:** 선형대수·미적분·확률이 모두 선행이고, AI 기능을 붙일 자기 서비스가 있어야 캡스톤이 성립하기 때문입니다.

J6은 J3 직후부터 J4·J5와 병렬로 둘 수 있습니다. 다만 메인은 한 번에 하나라는 원칙에 따라 실제로는 J5 뒤에 순차로 진행합니다. 진단에서 Java 경험이 확인되면 J1·J2는 1단계 규칙 7에 따라 "통과 기준 시험만"으로 줄입니다.
